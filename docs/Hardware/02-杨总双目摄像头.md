# 杨总独立双目摄像头：JHH2

## 验证状态

- **已在项目中实现**：`banana` 配置将独立 JHH2 识别为 `1bcf:2d50`；不与 SixCam JHH02 同 USB bus 的设备依次分配给 `jhh2_left`、`jhh2_right`，目标为 3840×1200@30。项目输出 H.265 MKV、`.y8` 与 IMU JSONL。
- **未完成板端验收**：`docs/TODO.md` 明确记录，Nori Xvision SDK 到纯 Linux V4L2/UVC 的项目级迁移尚未在 RK3588 板端编译或运行。因此不能将当前迁移实现表述为现场可用或端到端已验证。
- **历史资料**：`11-摄像头/01-双目摄像头信息.md` 记录设备名 JHH USB3.0 Camera、VID/PID `1bcf:2d50`、序列号 JHH003，以及 macOS 枚举的 3840×1200 格式。

## 基本信息

| 项目 | 当前项目／历史资料 |
|---|---|
| 设备类别 | 杨总独立双目，项目名称 JHH2 |
| USB 标识 | `1bcf:2d50` |
| 当前目标采集参数 | 3840×1200@30 |
| 当前输出 | H.265 MKV、`.y8`、IMU JSONL |
| 历史序列号 | JHH003（历史 macOS 枚举，待现场复核） |

## 历史格式记录

历史资料记录 macOS 的 `420v`（NV12）为 3840×1200，支持 30／25／20／10 fps，且该次枚举未列出 MJPEG。该记录用于追溯，不等同于当前 Linux V4L2 枚举结果；格式、可用帧率及设备序列号均需在目标板与实物上复核。

## 发现与采集

项目通过 V4L2 sysfs 扫描 USB 视频设备。`1bcf:2d50` 若与 `1bcf:2d51` 的 JHH04 同 bus，则作为 SixCam 的 JHH02；其余 `1bcf:2d50` 才作为独立 JHH2 左／右通道。该规则是当前发现实现，不构成物理接线或镜头排列的证明。
