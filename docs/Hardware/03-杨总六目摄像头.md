# 杨总六目摄像头：SixCam

## 验证状态

- **已在项目中实现**：SixCam 由 JHH02（双目侧）与 JHH04（四目侧）配对发现。项目以相同 USB bus 将 `1bcf:2d51` 的 JHH04 与 `1bcf:2d50` 的 JHH02 配对；目标分别为 3104×480@30 与 4000×1200@30。
- **未完成板端验收**：项目级 Nori Xvision 到 V4L2/UVC 迁移尚未在 RK3588 板端编译或运行；`docs/TODO.md` 要求完成 SixCam 和 Mango 全量等验证。当前实现不能替代板端验收。
- **历史资料**：`11-摄像头/02-六目摄像头信息.md` 记录 JHH04 的 macOS 枚举与视频格式；其内容须同当前实物及 Linux 枚举分别复核。

## 模组组成与项目输出

| 通道 | 角色 | USB 标识 | 当前目标采集参数 | 当前项目输出 |
|---|---|---|---|---|
| JHH02 | 双目侧 | `1bcf:2d50` | 4000×1200@30 | H.265 MKV、`.y8`、IMU JSONL |
| JHH04 | 四目侧 | `1bcf:2d51` | 3104×480@30 | `.y8`、IMU JSONL |

项目以同一 bus 作为 JHH02/JHH04 的配对条件；这是软件发现约束，并非对物理连线方式的描述。

## JHH04 历史格式记录

历史 macOS 资料将设备名列为 JHH04，并记录如下格式：

| FourCC | 说明 | 分辨率／帧率 |
|---|---|---|
| `420v` | NV12 | 3104×480@30 |
| `yuvs` | YUYV | 3104×480@5 |

历史资料未列出 MJPEG。这些仅是该次历史枚举结果，不能推断当前 Linux 格式集合、实际吞吐量或驱动支持情况。

## 镜头布局

历史资料曾列出 3104×480 对应的多种六镜头排列可能性，但没有实物证据确认其中任何一种。六镜头的物理排布、各镜头与画面区域的对应、线缆和供电均为待确认事项，本页不作推断。
