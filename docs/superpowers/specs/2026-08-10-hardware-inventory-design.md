# 硬件档案梳理设计

## 目标

在 `docs/Hardware/` 建立统一采集方案已使用硬件的可追溯档案，覆盖郭总摄像头、杨总双目与六目摄像头、腕部摄像头、AS5600 磁编码器和 VIVE Tracker。

## 文档结构

- `README.md`：设备总览、来源说明、验证状态定义与跨设备待办索引。
- `01-郭总摄像头.md`：YCTC SC233HGS 双目设备。
- `02-杨总双目摄像头.md`：JHH USB3.0 Camera / JHH2 独立双目设备。
- `03-杨总六目摄像头.md`：JHH02 与 JHH04 组成的六目模组。
- `04-腕部摄像头.md`：Nori SL 与 JHHSW 左右腕设备。
- `05-AS5600磁编码器.md`：I2C 磁角度传感器。
- `06-VIVE-Tracker.md`：VIVE Tracker 3.0 姿态采集设备。

## 信息规则

每篇设备页包含设备身份、接口与数据、项目集成、验证状态和待办五部分。具体信息以当前项目源代码、部署配置和板端验收记录为优先证据；`11-摄像头/` 中的历史资料作为补充来源。无法由当前材料证实的型号细节、物理镜头布局、附件和接线不得推断，必须标注为待确认。

## 验证状态

- **已在项目中实现**：当前源码或配置直接支持。
- **已板端验收**：项目文档记录了实际 RK3588 验收结果。
- **历史资料**：仅在历史采集资料中出现，尚未在本次项目资料中再次证实。
- **待确认**：需要检查实物、USB/I2C 枚举、接线或现场采集才能确认。

## 验收标准

1. 总览能链接到六篇设备档案并列出每类硬件的型号、接口和状态。
2. 设备档案中的型号、VID/PID、分辨率、帧率、采样率和输出类型均能追溯到项目或历史资料。
3. 所有资料缺口均以可执行的待办事项呈现，不将推测表述为事实。
4. 文档中的相对链接有效，Markdown 结构可被常规渲染器正确显示。
