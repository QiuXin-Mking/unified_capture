# unified_capture 系统质检需求

> 面向 unified_capture 统一采样系统的数据质检需求清单与发散分析。
> 定位：采集后离线质检 + 采集时实时告警的**需求来源**，不涉及具体实现。
> 更新：2026-08-20

| 30 | 产物完整性 | 检查文件大小是否合理（检测只有封装头、无帧数据的异常小文件）。 | 文件 < 阈值（如 MKV < 1KB） | P1 | 检查文件大小下限阈值 |

| 32 | 产物完整性 | 检查 Y8 字节数 = 宽 × 高 × 帧数（检测未落盘帧 / 尺寸变化）。 | 字节数 ≠ 宽 × 高 × 帧数 | P1 | 计算 Y8 字节数 = 宽×高×帧数 |
| 33 | 产物完整性 | 检查实际帧率是否达到标称 30fps。 | 实际 fps < 29 | P1 | 帧数/时长核算实际 fps |

| 35 | 系统健康 | 检查编码器错误（MPP H.265 编码失败帧数）。 | 编码失败帧数 > 0 | P1 | 统计 MPP 编码返回码/错误日志 |
| 36 | 系统健康 | 检查磁盘写入速率与剩余空间是否足够（掉帧常见于写盘慢 / 空间不足）。 | 写入速率 < 码率，或剩余空间 < 阈值 | P1 | 监控写入速率与 df 剩余空间 |
| 37 | 系统健康 | 检查 FIFO 是否溢出（生产者快于消费者）。 | 溢出计数 > 0 | P1 | 检查 ffmpeg 子进程 FIFO 溢出日志 |
| 38 | 系统健康 | 检查 CPU / 内存 / 温度是否异常（满载 / 温控降频导致掉帧）。 | CPU 持续 >90% / 温度超阈值 | P2 | 读取 /proc/stat 与 thermal 温度节点 |
| 39 | 系统健康 | 检查 sensor 线程是否存活、barrier 是否超时。 | barrier 超时 / 线程异常退出 | P1 | barrier 超时检测/线程存活状态 |
| 40 | 合规性检测 | 人脸检测：画面出现人脸（敏感数据）→ 标记本组视频不合规。 | 检测到人脸即判不合规 | P1 | 人脸检测模型扫描抽帧 |
| 41 | 合规性检测 | 人手检测：画面长时间无人手 → 标记本组数据不合规。 | 连续无人手时长 > 阈值（如 >30s） | P1 | 手部检测模型扫描抽帧 |
| 42 | 合规性检测 | 敏感信息检测：画面出现屏幕 / 证件 / 文档等 PII → 标记不合规。 | 检测到屏幕 / 证件 / 文档即判不合规 | P1 | 屏幕/证件/文档目标检测模型 |

## 1. 背景与范围

unified_capture 在 RK3588 上采集多路视频与传感器数据，产物被下游用于 AI 分析（人手/人脸/姿态识别）。质检的目标是：**在数据交付给 AI 之前，尽可能自动发现「传感器丢数、画面不可用、时间戳错乱、数据损坏、合规不满足」等问题**，避免把废数据喂进训练/推理流程，浪费算力并污染结果。

按产品形态，产物差异如下（质检项需按 profile 区分）：

| Profile | 视频产物 | 传感器产物 | 备注 |
|---------|---------|-----------|------|
| mango | H.265 MKV ×4（jhh02/jhh04/左腕/右腕） | 异步 IMU JSONL；jhh04 额外 Y8 | 无 MAG、无 AS5600、无 VIVE |
| banana | H.265 MKV + Y8 + IMU JSONL（jhh2 双/六目） | AS5600 JSONL、VIVE pose JSONL | legacy 头部 |
| cherry | H.264 MKV（3200×1200） | imu.jsonl / mag.jsonl / frame_meta.jsonl / video_frames.jsonl | 有 MAG 与 FRAME_META |

## 2. 原始需求清单（已梳理）

按「数据层」重新归类，便于后续映射到实现模块。

### 2.1 传感器数据完整性（丢数）

| ID | 检查项 | 判定标准 |
|----|--------|---------|
| Q-01 | 每帧 IMU 数据量 | 每帧应含 **10 个** IMU 样本，少于 10 判定为 IMU 丢失 |
| Q-02 | 每帧 MAG 数据量 | 每帧应含 **10 个** MAG 样本，少于 10 判定为 MAG 丢失 |
| Q-03 | 视频帧丢失 | 标称 30fps，按帧计数/时长核算实际 fps，低于阈值判定丢帧 |

> Q-01/Q-02 依赖 FRAME_META（cherry 的帧同步脉冲产物）建立「帧 ↔ 样本」的关联；mango/banana 无 FRAME_META，需按时间窗（每帧 1/30s）匹配 IMU JSONL。

### 2.2 传感器量程（超限）

| ID | 检查项 | 判定标准 |
|----|--------|---------|
| Q-04 | IMU 量程 | 加速度计/陀螺仪样本超过传感器量程（如 ±8g/±2000dps 的饱和值）判定超量程 |
| Q-05 | MAG 量程 | 磁场样本超过量程（如 ±4.9G 饱和）判定超量程 |

### 2.3 画面质量

| ID | 检查项 | 判定标准 |
|----|--------|---------|
| Q-06 | 画面全黑 | 亮度均值/直方图接近全 0，判定全黑 |
| Q-07 | 画面模糊（焦距错误） | 清晰度指标（Laplacian/梯度能量）持续低于阈值，判定失焦 |
| Q-08 | 过曝 | 高亮区域占比过高，直方图右端截断，判定有效细节丢失 |

### 2.4 底层报错

| ID | 检查项 | 判定标准 |

## 3. 发散扩展（值得补充的质检需求）

> 优先级：**P0** = 数据有效性硬门槛，缺了就废；**P1** = 强烈建议；**P2** = 锦上添花/排障辅助。
> 「已有雏形」标注说明当前代码已部分覆盖，可沉淀为硬验收。

### 3.1 多流时间同步（已有雏形 → 补成硬验收）— P0

现有 `deploy/calc_cherry_sync.py`、`calc_cherry_frame_imu_sync.py`、`calc_sync_exp_start.py`/`calc_sync_exp_end.py` 已做「IMU↔MAG↔FRAME_META」的时间对齐统计，但目前只是**离线报告脚本**，未纳入「通过/不通过」判定。建议：

- **视频帧 ↔ IMU/MAG 时间戳对齐**：每帧视频应落在对应时间窗的 IMU/MAG 样本内；偏差超阈值（如 >10ms）判定不同步。
- **多摄像头帧对齐**：jhh02/jhh04/左右腕的首帧与相邻帧 PTS 是否一致（六目模组各目曝光应同一时刻触发）。
- **MKV 容器 PTS ↔ JSONL 时间戳一致性**：容器内部时间戳与外部传感器时间戳应属同一时钟域（`g_t0` CLOCK_MONOTONIC 纪元），防止「视频和传感器各说各话」。

### 3.2 产物完整性（文件级）— P0

- **必需产物存在且非空**：cherry 要求 MKV + imu.jsonl + mag.jsonl 非空（frame_meta 允许空文件是合法的，见 README）；mango 要求每路 MKV + IMU JSONL 非空。
- **文件大小合理性**：检测「只有封装头、无实际帧数据」的异常小文件（如 <1KB 的 MKV）。
- **JSONL 合法性**：每行可解析为合法 JSON，且**最后一行完整**（断电/中断导致末行截断很常见）。
- **产物数量与 session 元数据一致**：实际输出文件与 profile 声明的一致（不多不少、无重复时间戳文件名）。

### 3.3 MKV 封装完整性 — P0

断电/强杀是嵌入式采集的常见失败模式，MKV 若未正确 finalize 会无法播放或丢尾部：

- 用 `ffprobe` 校验 MKV 可解析、时长 >0、帧数 >0；
- 检测「未 finalize / truncated」导致的尾部索引缺失。

### 3.4 传感器数据内容质量（时间序列）— P0

「每帧 10 个」只保证数量，不保证数据本身有意义：

- **卡死/恒定值检测**：IMU/MAG 持续输出恒定值（零值或饱和值）而非常见噪声 → 传感器卡死。检查窗口内方差接近 0。
- **采样率稳定性与样本分布**：10 个样本应均匀分布在帧周期内；检测相邻样本间隔抖动过大、样本「堆在一起」的情况。
- **静止偏置合理性**：静止时加速度计模长应 ≈ 重力（9.8 m/s²），陀螺仪应 ≈ 0；偏置过大说明标定丢失或传感器异常。
- **磁力计模长合理性**：MAG 模长应 ≈ 当地地磁场强度（约 50μT）；模长异常提示铁磁干扰或传感器故障。
- **温度寄存器**（若 IMU/MAG 暴露）：温度越限提示传感器过热/异常。

### 3.5 画面质量进阶 — P1

Q-06~Q-08 只覆盖全黑/模糊/过曝三个极端，常见废数据还有：

- **画面冻结（卡帧）**：连续多帧像素完全相同（传感器/解码器死机但仍发帧）。与「丢帧」互补——一个是有帧不更新，一个是帧都没了。
- **花屏/绿屏/坏块**：解码错误、传输损坏的可视化表现，可用坏块/异常色检测。
- **频闪/横纹**：曝光频率与电源 50/60Hz 不匹配导致的亮度周期性波动，检测帧间亮度周期性抖动。
- **偏色/白平衡异常**：各通道均值比例严重失衡。
- **欠曝（局部过暗）**：与过曝相对，暗部细节丢失。
- **镜头脏污/遮挡**：画面持续存在固定遮挡物（可用帧差后固定区域检测）。
- **分辨率/比例异常**：实际帧尺寸与配置不符（如 3104×480、4000×1200）。

### 3.6 时间戳进阶 — P1

- **单调性**：PTS 严格单调递增（Q-10 的回退检查），建议按整条时间线做全局检查而非局部。
- **跨设备时钟域一致性**：AS5600、VIVE、IMU、视频是否共享 `g_t0` 纪元；不同时钟源混用会导致同步分析失效。
- **长时间时钟漂移**：长时间采集（>30min）下时钟漂移是否可接受。

### 3.7 底层系统健康 — P1

- **V4L2 帧统计**：`VIDIOC_QUERYBUF`/`DQBUF` 错误、buffer 下溢、`V4L2_BUF_FLAG_ERROR` 计数。
- **USB 层错误**：dmesg 中的 UVC 丢帧/重传（`URB` 错误、`device descriptor` 异常）。
- **编码器错误**：MPP H.265 编码失败帧数、编码器 reset 次数。
- **磁盘写入速率/空间**：H.265 码率 + Y8 + JSONL 的持续写入是否跟得上（掉帧常见于写盘慢）；SD 卡剩余空间是否足够整个 session。
- **FIFO 溢出**：ffmpeg 子进程的 FIFO 是否溢出（生产者快于消费者）。
- **CPU/内存/温度**：板端资源占用，编码掉帧常与 CPU 满载、温控降频相关。
- **线程健康**：sensor 线程是否存活、barrier 是否超时、有无线程卡死（`wait_all_arrived` 超时）。

### 3.8 跨产物计数一致性 — P1

- **帧数 ↔ 时长 ↔ 帧率**：帧数 ≈ 时长 × 30，核对实际 fps。
- **Y8 字节数 ↔ 帧数**：Y8 文件字节数应 = 宽 × 高 × 帧数，不一致说明有帧没落盘或尺寸变了。
- **各摄像头 MKV 时长一致性**：六目各目 + 腕部时长应一致，某路明显偏短说明该路掉流。

### 3.9 合规/敏感数据扩展 — P1

- **其他人脸/PII**：画面出现屏幕、证件、文档等可识别个人信息，标记不合规。
- **音频合规**（若未来腕部麦克风启用）：敏感语音检测。当前版本不采集音频，此项作为预留。

### 3.10 工程化质检能力 — P2

- **质检报告产出**：每个 session 生成一份结构化质检报告（JSON/HTML），汇总所有 check 的通过/失败与具体指标。
- **阈值可配置**：不同场景/传感器型号（量程、fps、亮度阈值）不同，阈值应进配置而非硬编码。
- **实时 vs 离线双模式**：采集时实时告警（及时止损） + 采集后离线全量分析（交付前把关）。
- **质检可追溯**：报告与 session 元数据绑定，问题可回溯到具体设备/通道/时间点。
- **软/硬失败分级**：区分「必须拦截」的硬失败（无帧、无 IMU、损坏）与「警告」的软失败（轻微模糊、轻微过曝），避免过度拦截。
