# 项目介绍（产品向）

> 面向非技术读者：介绍这套系统「做什么、有哪些产品形态、怎么用」，不含代码与技术实现细节。

## 项目定位

一套运行在 **RK3588 芯片**上的**具身智能数据采集统一平台**。配合 device-ui 前端页面（React 工程），为机器人 / 具身智能应用采集**多路同步的视觉与运动数据**，供后续训练与分析使用。

## 支持的产品形态

平台通过一个 **profile 配置文件**即可在多种硬件产品间快速切换——不同规格产品的采样需求，改一份配置即可适配，无需重写程序。

| 产品 | 内部代号 | 说明 |
|------|---------|------|
| ego | mango | 头部穿戴式 + 左右腕部，分四档规格 |
| umi | banana | 头部设备，含独立双目 + 六目 + 角度 / 位姿传感器 |
| （规划中） | cherry | 后续产品 |

### ego（mango）系列规格

| 规格 | 屏幕 | 摄像头 |
|------|------|--------|
| mango pro plus | 有屏幕 | 六目 |
| mango pro | 无屏幕 | 六目 |
| mango plus | 有屏幕 | 双目 |
| mango | 无屏幕 | 双目 |

### umi（banana）

头部穿戴式设备，除视频与 IMU 外，额外采集角度与空间位姿：

| 硬件 | 说明 |
|------|------|
| JHH2 独立双目 × 2 | 左右两路，各 3840×1200@30，H.265 视频 + IMU |
| 六目模组 | 双目侧 4000×1200 + 四目侧 3104×480 |
| AS5600 磁编码器 | 角度传感器，100 Hz |
| VIVE Tracker | 空间定位 / 6DoF 位姿 |

数据输出除各相机目录外，顶层还含角度（`encoder-*.jsonl`）与位姿（`tracker*.jsonl`）数据文件。

## 核心能力

1. **多路视频 + 运动数据同步采集**：视频与运动数据（加速度、角速度、磁场等）逐帧对齐，开箱即同步。
2. **profile 一键切换产品规格**：不同档位产品的采样需求，一份配置即可适配，扩展新硬件只加配置、不改程序。
3. **配合 device-ui 前端页面（React 工程）**：远程控制启停、状态查询与画面预览。
4. **数据安全落盘**：录制内容写入 SD 卡，拔卡即取，意外断电不丢数据。

## 核心价值

- **一套平台、多档产品**：同一套软件覆盖多档硬件规格，显著降低研发与维护成本。
- **数据即用**：视频与运动数据天然同步对齐，可直接用于具身智能的模型训练与行为分析。
- **上手门槛低**：佩戴后按键即用，也可由前端页面远程控制。

## 数据存储

所有采集数据**只写入 SD 卡**，不上云、不依赖网络。

每次录制生成一个「会话」目录（`session_001`、`session_002`…），每路相机一个子目录，内含该路的视频与运动数据文件：

```
SD 卡
└── 录制任务 / session_001/
    ├── 头部双目（jhh02）/    → jhh02-<时间戳>.mkv  +  jhh02-<时间戳>.jsonl
    ├── 头部四目（jhh04）/    → jhh04-<时间戳>.mkv  +  jhh04-<时间戳>.y8  +  jhh04-<时间戳>.jsonl
    ├── 左腕（wrist_left）/   → wrist_left-<时间戳>.mkv  +  wrist_left-<时间戳>.jsonl
    └── 右腕（wrist_right）/  → wrist_right-<时间戳>.mkv  +  wrist_right-<时间戳>.jsonl
```

**文件格式**：

- **视频（`.mkv`）**：H.265 高清编码，30 帧/秒，可用通用播放器 / 分析工具打开。
- **Y8（`.y8`）**：jhh04 的无头灰度帧串流，按 `gray8`、`3104×480`、`30fps` 读取，每帧 `3104×480` 字节。
- **运动数据（`.jsonl`）**：纯文本，每行一条记录，与视频逐帧对齐，包含三类数据：
  - **IMU**（加速度 + 角速度）：`ax/ay/az_mg`（毫 g）、`gx/gy/gz_mdps`（毫度/秒）
  - **MAG**（磁力计）：`magx/magy/magz_ut`（微特斯拉）
  - **温度**：`mag_temp_c`（摄氏度）

示例（对应视频第 123 帧，两类样本混写在同一文件）：

```json
{"frame_idx":123,"t_us":45678,"ax_mg":-12.345,"ay_mg":0.123,"az_mg":998.7,"gx_mdps":-10.2,"gy_mdps":0.5,"gz_mdps":1.1,"exp_start_us":1000,"exp_end_us":2000}
{"frame_idx":123,"t_us":45678,"magx_ut":-12.3,"magy_ut":45.6,"magz_ut":78.9,"mag_temp_c":25.0,"exp_start_us":1000,"exp_end_us":2000}
```

> 目录结构随产品规格（六目 / 双目，是否含腕部）由 profile 决定，上图为「六目 + 双腕」配置的示例。

## 技术规格（相机分辨率与数据流转）

> 本节为技术补充：说明每路相机的分辨率 / 帧率，以及数据从相机到最终文件的格式流转。

### 相机分辨率与帧率

| 相机 | 接口 | 分辨率 | 帧率 | 码率 |
|------|------|--------|------|------|
| jhh02（六目双目侧） | `1bcf:2d50` | 4000×1200 | 30fps | 16 Mbps |
| jhh04（六目四目侧） | `1bcf:2d51` | 3104×480 | 30fps | 4 Mbps |
| 左腕 wrist_left | iProduct `SL` | 1440×960 | 30fps | 8 Mbps |
| 右腕 wrist_right | iProduct `JHHSW` | 1440×960 | 30fps | 8 Mbps |

### 数据格式流转

相机输出 **MJPEG**，经解码、打包、硬编码、封装，最终生成 **MKV 视频** 与 **JSONL 数据**：

```
相机（USB/UVC）→ V4L2 取帧 → MJPEG
   → libturbojpeg 解码 → YUV420（Y 亮度平面 + UV 色度平面）
       ├─[IMU]  读 Y 平面顶部码带 → ImuSensor 异步解析 → JSONL（IMU / MAG / 温度）
       └─[视频] yuv_to_nv12 → NV12 → Rockchip MPP 硬编 → H.265 裸流
                   → FIFO → ffmpeg 封装 → MKV
```

| 步骤 | 模块 | 输入格式 | 输出格式 |
|------|------|----------|----------|
| 取帧 | 内核 UVC / V4L2（`/dev/videoN`） | — | MJPEG |
| 解码 | libturbojpeg | MJPEG | YUV420 |
| IMU 提取 | 读 Y 平面码带 → ImuSensor | Y 平面 | JSONL |
| 打包 | yuv_to_nv12 | YUV420 | NV12 |
| 硬编 | Rockchip MPP | NV12 | H.265 裸流 |
| 封装 | ffmpeg（`-f hevc -c copy`） | H.265 裸流 | MKV |

关键点：

- **视频不二次压缩**：MJPEG 只解一次码，MPP 硬编一次，ffmpeg 用 `-c copy` 直通封装，不重编码，画质无损、CPU 占用低。
- **IMU 寄生在视频里**：IMU 数据被编码成图像顶部一条码带随视频传输，解码时从 Y 平面顶部抠出，天然做到 IMU 与视频逐帧对齐，无需额外数据通道。

## 使用流程

1. 选择对应产品规格的 profile 配置；
2. 佩戴设备、开机；
3. 按键（或前端页面点「开始」）→ 执行动作 / 任务 → 停止；
4. 拔出 SD 卡，交给后续分析。
